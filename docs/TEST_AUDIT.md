# Behavior-first test audit implementation

This implements the reviewed September 15 audit against `fbe1205d8558b9362a341a0f9c78b596fb75a684`, after PR #6 merged. The release drift checks and MCP error-provenance envelope from that PR are preserved. The initial audit's 107 inventory-only files are **not** approved for deletion or claimed as reviewed by this change. One such file, `foundry/test/pramana_foundry/coordinator_test.exs`, was read narrowly during validation after it reproduced a global fixture-path leak; only setup/teardown isolation was changed, not its behavior assertions.

## What matters

A useful test distinguishes the intended behavior from a plausible wrong implementation. Positive and negative controls belong together: a filter needs matching decoys, an ordering check needs unequal scores, a capacity check needs both a free and a full pool, and a no-effect claim needs a recorded effect boundary. Small tests at different boundaries are not redundant merely because they exercise the same underlying function.

Coverage is diagnostic, not an acceptance target. This PR does not lower the core/web ratchets, silently widen exclusions, or claim an unmeasured coverage or runtime gain. The core coverage exclusion currently includes behavioral `Pramana.Corpus.*` modules, not just schemas; a coverage report using that exclusion must not be described as full domain protection. Ordinary CI runs `mix test`, whereas the local phase gate owns its coverage/corpus checks. Saved benchmark artifacts are historical evidence, not a recomputation of current performance.

## Ownership and organization

The former large reader suite is split into search, passage, work, survey, inventory and provenance modules with a small shared fixture builder. Every retained test has one capability owner. Pure report parsing, evaluation case contracts, chunk grouping, hybrid fusion/confidence/depth and Foundry PM/quota/preparation policy now live separately from database or global-state cases. This avoids unnecessary per-test seeding; it does **not** claim the complete umbrella can boot without PostgreSQL.

CI forces the project compile so restored Rustler build metadata cannot hide a missing shared library, and uses `mix release --overwrite` so a cached release cannot masquerade as a new build. The native companion now has deterministic Rust tests for maximal reuse, Unicode scalar offsets, self-reuse rejection and the seed-frequency boundary, and CI explicitly runs that companion's tests. Its tokenizer FFI test asserts a search-specific overlapping token rather than merely accepting equal token counts.

## Validation and limits

The pinned Foundry toolchain (Elixir 1.20.3, OTP 29.0.5) and locked public Owl dependency were used in an isolated scratch environment. The unchanged baseline had 432 passing tests and one explicitly excluded optional tokenizer recomputation. After removing only reviewed legacy duplicates and adding stronger boundaries, the Foundry run contains 427 tests; the difference is not a quality metric. Focused affected suites and full-suite runs exercise the actual implementation and real subprocess boundaries, not merely static source checks.

The local environment has no Pramana/PostgreSQL dependencies or Cargo. GitHub CI at head `aea88144cb82b44e08653f564fdb3b4800a0410d` ran the whole source-only Pramana umbrella: 1,529 core checks, 295 web checks and 7 native checks passed, with 16 corpus-dependent checks explicitly excluded. Its four Rust companion tests and Dialyzer also passed. The job still failed one Credo alias check; the dependency-free documentation job exposed a runtime-module dependency. Both are corrected in the follow-up, which must itself pass CI before merge. Foundry passed 427 checks (one optional tokenizer recomputation excluded) locally with alternate ordering and in isolated CI. The updated model-free documentation suite passed all 42 checks locally.

No real-provider run, daemon activation, corpus maintenance, paid execution, database migration against user data, coverage measurement or performance benchmark is performed by these tests. Shared test fixtures and test-only state are isolated; production runtime state is not touched. Commit/CI evidence belongs in the PR record rather than a permanently asserted numeric target.

## Remaining validation boundaries

The preserved dependency versions were not upgraded here. During validation, Hex resolution emitted advisory warnings for the existing Bandit and Mint versions even though `mix deps.audit` returned success; the test-suite changes do not establish dependency security. No full-corpus evaluation, HNSW scale benchmark, coverage measurement, live provider run or production activation was performed.
