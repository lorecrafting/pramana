## What the candidate actually needs

Findings 1 and 2 are one gap: the PM role has no execution lifecycle in the event vocabulary. The
ticket roles each have plan → observe/close → settle, with the settle naming its execution. A
correct R4a.03.f2 needs:

- a PM success-path close event (or `pm_proposal_recorded` defined as closing the open planning
  execution — a contract reading, not a code choice), and
- `pm_launch_settled` carrying `execution_id`, which is a payload change owing matching edits in
  `transition_plan.ex` and `record_codec.ex`.

That is a vocabulary change, not a guard. It is recorded here rather than built because it widens
the reference kernel's surface, and the standing direction (2026-09-22) is to stop growing that
surface except for correctness fixes until the orchestrator boundary exists. R4a.03.f2 stays
`{:unguarded}` in `r4_coverage_test.exs`, which is the truthful classification.
