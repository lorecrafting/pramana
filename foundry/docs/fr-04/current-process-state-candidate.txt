## Correction boundary

`ProcessGroup.identity/1` now reads the actual `ps` process-state column. A bound
leader is gone only when its PID is absent or an observation with the same PID,
process-group ID, and start time has state `Z`. Command text is never death evidence.
`presence/1` preserves mismatched/recycled identity and observation failure as
`:unknown`; `gone?/1` therefore cannot turn either case into cancellation success.
Nonempty `ps` diagnostics are observation failures rather than absence.

Both the failed group-signal race and `Checks.Runner.terminate/3` now recheck the full
caller-bound identity. The permanent model-free cases distinguish a live argv containing
`defunct`, a real forked zombie, an absent PID, a recycled/mismatched identity,
observation failure, failed `kill`, and the cancellation caller. The fixtures signal no
foreign process; live marker processes are owned Ports and the injected failed-signal
runner does not execute `kill`.
